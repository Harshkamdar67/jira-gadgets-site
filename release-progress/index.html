Release Progress

A Jira Cloud dashboard gadget. It lists the releases (fix versions) in a project, shows how much of each is done, and estimates whether each will be ready by its release date.

Release Progress is not on the Atlassian Marketplace yet. This page describes how it works so you can judge it before it is listed.

Add it to a dashboard

  1. Open a dashboard and select Edit.
  2. Select Add gadget, search for Release Progress, then select Add.
  3. Pick a project, choose which versions to show and how to measure progress, then select Save.

To change the settings later, edit the dashboard, open the gadget's ⋯ menu and select Configure.

Settings

SettingWhat it does
ProjectThe project whose versions to show. Company-managed and team-managed projects both work.
Which versionsAll unreleased versions, which picks up new versions as they are created, or Choose versions to tick specific ones. Archived versions are never shown.
Measure progress byIssues (done of total), Story points (points done of points estimated) or Time (hours logged of hours estimated, including sub-tasks).
SortRelease date (versions without one go last), least complete first, most work remaining, or the order on Jira's Releases page.
Show up to1 to 30 versions.
Show completion forecastsShow the forecast line under each version.

Summary line

When the gadget shows two or more versions, a line at the top adds them up, for example 43% done · 4 releases · 1 overdue. The percentage uses the measure you chose in the settings. Each flag appears with the number of versions that have it, and flags no version has are left out.

What's left

Each version with unfinished work has a What's left (N) link, where N is the number of open issues in it. Select it to list them under the version:

  • In-progress issues come first, then to-do issues. Within each group the order is Jira's rank.
  • Each row shows the status, the issue key, the summary, and the assignee or Unassigned. Select the key to open the issue.
  • Only the first 15 open issues are listed. If there are more, a N more open in Jira link opens a Jira search for the rest.

Select a version's name to open it in Jira. In company-managed projects that is the version's release page. In team-managed projects without the Releases feature, Jira shows a search for the version's issues instead.

Unestimated issues

When you measure by story points or time, an issue with no estimate can't count toward the bar, so the bar can look further along than the work is. The gadget says so next to the totals, for example 13 of 42 pts · 3 not estimated.

  • A story point estimate of 0 counts as estimated.
  • If nothing in the version is estimated, the count is left out, because the line already reads No estimates.

Release dates

The gadget uses the version's Release date and shows it as, for example, Release Oct 29. It turns amber when the date is a week or less away and red once it has passed. A version without a release date says No release date, gets a forecast, and is never flagged at risk or overdue.

Once a version is released, All unreleased versions drops it. A version you ticked under Choose versions stays, with a Released tag and no flags or forecast, until you untick it. Released versions can't be newly ticked.

Forecasts

Each unreleased version shows a line such as Likely done Nov 14 · 85% sure by Nov 27. The gadget looks at how many of the version's issues were finished in each recent week, then runs 1,000 simulations of the remaining work at those weekly rates. Estimates aren't used.

Hover over the forecast line to see what it's based on, for example: Based on 11 issues finished in the last 6 weeks (about 1.8 a week), with 6 left. Likely is the middle of 1,000 simulated futures; 85% sure means 85 in 100 finish by then.

  • History starts when the first issue was given the version, not when the issues were created. A version filled with old backlog issues last week has one week of history, not two months of empty weeks. The gadget reads this from each issue's Fix Version history.
  • Only up to the last eight weeks are used.
  • Forecasts need two weeks of history and at least three finished issues. Until then the gadget says so instead of guessing.
  • Forecasts count issues, whichever measure you show.

Risk flags

FlagMeaning
At riskThe cautious (85%) forecast lands after the release date.
OverdueThe release date has passed, the version isn't released, and work remains.
StalledNothing in the version has been finished in two weeks.
Scope growingMore issues were added to the version than finished in the last two weeks.

"Added" means given this fix version, so an old issue moved into the release last week counts as added last week. Select a flag to see the numbers behind it. For example:

  • At risk: The 85% forecast is Nov 19, 26 days after the release date (Oct 24). The team has been finishing about 1.8 issues a week, and 9 issues are left.
  • Overdue: The release date (Oct 17) passed 2 days ago, and 6 issues are still open.
  • Stalled: No issue in this release has been finished in the last two weeks. The last one was finished on Sep 30, 19 days ago.
  • Scope growing: In the last two weeks, 5 issues were added and 2 finished, so the open work grew by 3.

An at-risk version also gets a suggestion, for example: To finish by Oct 24 with 85% confidence at this pace, move about 4 of the 9 open issues out of the release, or move the release date to Nov 19. If even one remaining issue can't be finished in time at the current pace, it says so instead. The suggestion uses the same simulation as the forecast, counts issues rather than points, and assumes the team keeps its recent pace.

Good to know

  • Issues are found with the Fix Version field. Affects Version is not used.
  • Sub-tasks are left out of the counts, because their time is already included in their parent's time. Sub-tasks with their own fix version therefore don't add to the issue count.
  • An issue fixed in two versions counts toward both.
  • Story points are read from either "Story Points" or "Story point estimate", whichever your site uses.
  • Time is measured against the original estimate. Remaining estimate isn't shown.
  • Everyone sees only versions and issues they already have permission to view.
  • Up to 3,000 issues are counted per gadget. A note appears if that limit is reached.
  • If Jira doesn't return Fix Version history, forecasts and the scope flag fall back to issue creation dates. The gadget still loads.
  • The gadget only reads Jira. It never changes issues or versions.

Pricing

Planned: free for up to 10 users. Above that it will be priced per user and billed by Atlassian through the Marketplace. Prices will be on the Marketplace listing once it is published.

Your data

Release Progress only reads Jira data to draw the gadget. It stores nothing of its own beyond the gadget settings Jira keeps for every dashboard, and no data leaves Atlassian. See the privacy policy.
